# アーキテクチャ

## 構成

```text
MAUI Hybrid Blazor
  ├─ Razor UI
  ├─ Application / Sync service
  ├─ SQLite（TODO・同期キュー）
  └─ HTTP client ──> Spring Boot Web API ──> PostgreSQL
```

クライアントは SQLite を読み書きするため、API が停止中またはネットワーク未接続でも CRUD を継続できます。同期は UI 操作とは別の処理です。

## データ責務

| 層 | 保存内容 | 役割 |
| --- | --- | --- |
| SQLite | TODO のローカルコピー、同期キュー、同期状態 | UI の即時応答とオフライン操作 |
| PostgreSQL | 同期済み TODO、更新情報、論理削除情報 | サーバー側の共有・永続化 |

初期 PoC ではユーザー識別を導入しない場合、単一の論理ユーザーとして扱います。複数端末・複数ユーザーを検証する前に、すべての同期対象に `ownerId` を追加します。

## 同期フロー（提案）

1. ローカル CRUD 時に `TodoItem` を更新し、操作内容を同期キューへ追加する。
2. `POST /api/v1/sync` に未送信操作を UUID の操作 ID とともに送る。
3. API は操作 ID により同一要求の再送を冪等に扱い、成功・競合・検証エラーを項目単位で返す。
4. クライアントは成功分をキューから除去し、サーバーの正規データを SQLite へ反映する。
5. クライアントは `GET /api/v1/todos?updatedSince=...` でリモート変更を取得する。

## 競合方針

初期の候補は optimistic concurrency（`version` を比較）です。競合時は API が `409 Conflict` とサーバー側の最新レコードを返し、クライアントはユーザーに選択を委ねるか、PoC で採用した規則を明示して解決します。安易な last-write-wins はデータ消失の可能性があるため、採用する場合は明文化してから実装します。

## 時刻と ID

- ID は UUID をクライアント生成し、オフライン作成でも恒久 ID とする。
- 時刻は UTC の ISO 8601 文字列で API に送受信する。
- 同期カーソルはサーバー発行値を使う。端末時計だけを差分基準にしない。
